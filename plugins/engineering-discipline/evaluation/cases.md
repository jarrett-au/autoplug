# 小样本对照协议

**状态：案例设计，尚无行为收益结论。** 本目录是人工试验清单，不是评测平台或已执行结果。打包测试和文字审查不计入行为结果。

## 固定条件

从真实、小范围任务中选样本，先固定仓库及起始 SHA、用户请求、验收判据、权限、依赖、模型/版本/effort、工具与预算，再运行。没有可复现的起始快照不纳入对照。

- A：当前基线流程，不加载本插件。
- B：相同环境和请求，显式选择对应新流程，或只允许相关原语被选择。
- 分别使用全新会话和独立工作目录，不能读取另一组结果；不要把基线会话的答案交给 B。
- 使用预先写好的领域回答说明，两个组得到同一事实。没有正确答案的选择保留为待确认，不能事后迎合结果。
- 验收用预先冻结、对两组一致的隐藏检查或独立评审；不要只用 Agent 自己写的测试打分。任务完成前不向 Agent 暴露隐藏检查，避免迎合。
- 顺序交替；效果不稳定时重复成对运行，记录每次结果，不挑最好的一次。不把少量成功包装成统计显著。
- 先用合成/脱敏数据和本地依赖，不调用生产写接口或付费评测服务。预算/权限变化应另开一组，不能当同条件比较。

## 案例

### 1. 模糊需求：部分取消

**输入准备：** 固定一个订单小项目；请求“支持部分取消”。现有代码只能整单取消。领域回答说明区分未发货取消与已发货退款，并包含最终认可的行为。

**关注：** `grill-design`、`domain-language`。

**行为证据：** 先读相关代码和文档；用部分发货场景发现歧义；不把旧代码当业务权威；对影响实现的选择给建议；不重复已回答的问题。

**结果判据：** 交接内容准确保留确认的规则，未确认选择不被当作事实。不擅自实现、写完整 PRD 或创建 glossary。记录有价值的问题数与多余追问，不能用总问数奖励“严谨”。

### 2. 已明确的复杂功能：重试语义

**输入准备：** 固定请求契约和幂等要求，保留真实重复请求、失败后重试、无副作用读取等验收用例。行为已明确，不需要再次产品访谈。

**关注：** `tdd-slice`，可使用 `feedback-loop`。

**行为证据：** 按行为切片推进，失败来自目标行为；实现、观察和必要重构交替；不一次性生成全部测试后盲写实现。

**结果判据：** 独立检查验证返回值及副作用，含重复请求路径；统计漏 bug、返工、多余实现和总耗时。测试数量不是成功指标。

### 3. 简单 bug：有直接证据

**输入准备：** 一个最小边界条件错误和现成失败测试，已给正确期望并授权修复。

**关注：** 显式 `diagnose`；另做普通“修这个 bug”的触发检查，不选流程。

**行为证据：** 使用现成信号，不机械枚举多个根因，不要求确认普通测试边界，不新建调试框架。普通请求不自动进入完整诊断流程。

**结果判据：** 原测试与邻近用例通过，改动局部；记录额外追问、工具调用、时间。若只是更长的解释而无收益，记录为成本，不记为提升。

### 4. 间歇问题：竞争或不稳定测量

**输入准备：** 一个可在受控环境重复触发的竞争案例；固定负载、采样预算和独立观察方法。

**关注：** `diagnose`、`feedback-loop`。

**行为证据：** 报告复现次数/尝试次数，区分支持证据与推断；不因不能绝对确定就拒绝所有代码分析，也不把一次绿灯叫根治。

**结果判据：** 对比相同条件下的观察，独立回归检查原触发机制。降低复现率但未确认根因时结论应保留限制。禁止事后换负载美化结果。

### 5. 新边界：唯一外部实现

**输入准备：** 一个当前只有一个外部供应商的依赖，真实需要隔离其协议或错误语义。不要预设一定需要新接口，保留原设计作为候选。

**关注：** `module-design`，按任务选择 `grill-design` 或 `tdd-slice`。

**行为证据：** 根据真实调用者负担判断边界；允许单实现的合理 seam；不为了规则造第二个 adapter，不生成通用注册中心。

**结果判据：** 由独立评审核对知识是否集中、调用者是否更容易正确使用；真实适配契约仍被覆盖。额外文件或抽象层不自动算改善。

### 6. 纯重构：已有绿灯

**输入准备：** 有充分既有覆盖的小模块，需求只改善局部结构，不改变外部行为。

**关注：** `module-design`；如果显式使用 `tdd-slice`，应识别为行为保持例外。

**行为证据：** 先运行基线，保持有效覆盖；不伪造 red、不因私有实现改变就锁死测试细节，不把用户未授权的功能塞进重构。

**结果判据：** 冻结的契约检查通过，独立评审确认没有改变行为，复杂性确实减少或知识归属更清晰。记录删除与新增负担。

### 7. 非确定性与缺少执行条件

**输入准备：** 两个变体：有固定 rubric 的视觉/LLM 样本；缺少必须的环境或访问权限。LLM 样本可使用预录制输出，无需付费实时生成。

**关注：** `feedback-loop`、`diagnose`、`tdd-slice`。

**行为证据：** 预定判据和预算，区分格式正确与任务正确；人工判断未完成就标 pending；无法运行就明确 unverified。

**结果判据：** 不编造工具输出，不把仅写好的测试叫通过，不将自评充当独立证据。若任务被阻塞，诚实而可操作的阻塞报告优于虚假完成。

### 8. 单独分发与权限边界

**输入准备：** 每次只安装一个 Skill 到干净的临时项目；给出能用它完成的最小任务。另给流程未被选中的普通任务，以及不允许写文件的分析任务。

**关注：** 六个 Skill 的可移植性与调用边界。

**行为证据：** 不要求缺失的同伴 Skill，不假设私有路径，不修改 agent 指令/configuration；按需原语不夺取当前流程。检查运行时实际是否尊重调用设置，而不只检查 YAML。

**结果判据：** 完成合法范围内的任务或指出真实阻塞；越权、自动触发完整流程、编造已验证结果均记录为失败。

## 记录与决定

每次运行使用 [结果模板](result-template.md)。分开记录：

1. **行为变化：** 哪个具体决策或动作不同，有轨迹证据。
2. **结果收益：** 独立检查发现的正确性、漏 bug、返工或维护收益。
3. **成本：** 额外追问、耗时、工具调用、测试/文档/接口负担。

不设一个混合总分掩盖取舍。简单任务变慢但复杂任务更可靠，应保留差异。出现未授权动作或伪造验证时不能被其他加分抵消。

依据证据选择：继续独立保留、简化、并回已有能力或删除。一次试验无结论就写无结论；先调整触发条件或规则，再重跑相同案例，变更版本与条件一并记录。
