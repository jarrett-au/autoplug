# Project Context

Make current knowledge independently usable by the next session, not a better-maintained historical library. An adequate project may need no edits. Work independently; never automatically launch another workflow or require setup before development.

## 1. Bound authority

Read the request and project instructions. Identify scope, readers and write permission. An audit is read-only. Explicit requests to maintain project agent instructions authorize that scoped work; ordinary documentation requests do not. Where ambiguous, complete authorized work and propose instruction edits unsaved.

Reuse the existing agent entry and loading conventions. Do not duplicate AGENTS.md and CLAUDE.md. If no entry exists, resolve the target runtime; verify official loading rules before claiming automatic loading, or ask if unresolved. Do not modify global instructions, permissions, hooks, tool configuration, application code, deployment configuration, data or secrets.

Preserve unrelated/uncommitted work. Checkout behavior does not establish production state. Identify published-contract, operational/recovery and explicit retention responsibilities before removal. Externally consumed paths require an authorized caller/link migration plan. Existing restrictions on historical edits remain constraints; do not rewrite them merely to permit a broader cleanup.

## 2. Establish facts and dispositions

Read relevant entry points, contracts, code, tests and command definitions. Use examples instead of secrets; never launch production, migrations or paid calls to tidy docs. Code establishes behavior, not automatically intended requirements. Resolve material contradictions explicitly. Consult history only for a concrete unanswered question.

Before editing each candidate, decide its disposition and why; a short working list suffices, not a saved audit report:

- **Current authority:** update in place. Age or a dated filename alone does not make a document obsolete.
- **Mixed current knowledge and chronology:** extract still-valid rules into their current owner, then remove superseded plans, dated increments and execution narrative. The reader must not replay dates to derive current behavior. If the file itself is the owner, rewrite it as a coherent current contract.
- **Retained historical artifact:** identify a specific consumer, supported release, recovery dependency or retention obligation. Preserve its historical body rather than adding today's implementation, status banners or repaired historical links. Correct historical facts only when explicitly requested or when a material error in the original record is established.
- **Obsolete narrative:** remove after useful knowledge has a home. No closed-task shell, replacement archive or evidence ledger.
- **Unresolved dependency:** preserve the affected material and name the exact question; continue unrelated cleanup. Do not turn uncertainty into a blanket historical-library policy.

A code-comment reference, unique sentence, old test count or potential future usefulness is a lead to investigate, not sufficient retention justification. Determine whether a reference carries a real safety/compatibility obligation or is merely stale. Do not alter code or immutable migrations just to eliminate a documentation dependency. For justified retained material, point to it only from the specific relevant obligation, not a default history-reading catalogue.

For new projects, save only confirmed goals, constraints and necessary questions. Do not invent stack, commands, interfaces, architecture or reasons; missing decisions do not justify empty scaffolds.

## 3. Assign one owner

Prefer existing sections and locations. Split for independent stable readers or update boundaries, not length or feature names. Optional fallback homes, only when needed:

- README: purpose, operations, safe checks and short navigation.
- Existing agent entry: stable non-obvious constraints and reading/maintenance rules, not an encyclopedia or temporary task permissions.
- GLOSSARY.md or existing CONTEXT.md: domain meanings, not fields or progress.
- docs/architecture/overview.md: current responsibilities and cross-module invariants.
- docs/architecture/client-contract.md: caller obligations across features.
- docs/adr/: costly-to-reverse, surprising choices with real alternatives and consequences; no invented approvals or execution history.

These are not a required tree, index, template or file count. Keep approved but unimplemented intent separate from current capability. Link authorities rather than duplicate them. A new index must reduce navigation burden, not promote mixed historical records into current authorities.

## 4. Consolidate and close

Apply dispositions within scope. Redirect current inbound references to the extracted knowledge, or remove obsolete references; do not repair the entire historical graph to make a global link count green. Preserve active work, real backups, data, images, raw artifacts and explicit retention obligations. Removing narrative docs grants no permission to delete those objects.

Use the existing tracker for unfinished handoffs, or .scratch/<slug>.md only if needed. Keep scope, acceptance, confirmed choices/sources, unresolved questions and next action. Remove completed local tasks after valid knowledge moves, subject to explicit retention policy. External tracker changes require permission; never delete their history.

When authorized, reconcile brief project maintenance rules in the existing entry: one owner, current-state updates, task retirement and response-default verification. Do not paste this workflow into it or weaken safety rules to ease cleanup.

## 5. Verify usability, then links

Answer representative current questions from the resulting owners: behavior, responsibility, safe verification and real next work. Prefer a fresh reader given only current entry points; otherwise disclose self-review. An assertion that links exist is not a reader-comprehension test.

Then check links/anchors in the retained current reading surface and safe commands. Historical artifacts outside that surface need not have their old links modernized. Report unresolved dependencies, deployment limits and checks actually performed. Return changed/removed paths and the next entry; do not save a cleanup report. Repeat runs should leave adequate content unchanged, not reorder or rephrase it.
